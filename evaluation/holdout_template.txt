PHI Protect: held-out test set
==============================

Copy this file to evaluation/data/holdout.txt and replace the example prompts below with your own.

RULES
1. NEVER use real patient data. Invent every name, date and number. Do not take a real record and
   change a few characters. Make it up from scratch, but in the exact format you see at work.
2. Mark every value that must never reach an AI tool like this: {{phi:Maria Lopez}}
   Mark: patient / subscriber / guarantor names, DOB, dates of service, member / subscriber / group /
   claim / MRN / account numbers, SSN, Medicare ID, phone, email, street address, city, ZIP.
   Do NOT mark: dentist / provider names, practice names, payer names, NPI, TIN, CDT codes,
   dollar amounts, release dates, code identifiers like patient_id.
3. A prompt with no markers is a "clean" prompt. Aim for about 40% clean prompts, and make them look
   risky on purpose (SQL on patient tables, code with patient fields, EOB questions). They measure
   false alarms.
4. Put a line containing only --- between prompts. Prompts can span many lines.
5. Write what you would really paste into Claude / ChatGPT. Mix in:
   chat questions, JSON, CSV rows, logs and stack traces, SQL results, X12 837D / 835 / 270 / 271,
   EOB and denial text, emails and call notes, code with test fixtures, lowercase and typos,
   first names only, short names (Le, Ng, Wu).
6. Target 50 to 100 prompts. Different people writing them is better than one person writing all.

HOW IT IS USED
This set is for go / no-go checks only. Nobody tunes the detector while looking at it. When it finds
a problem, the fix gets its own regression test, and the set is refreshed with new prompts.

Run it with:
    uv run python -m evaluation.evaluate evaluation/data/holdout.txt

Everything above the first --- line is ignored.
